## 1. Problem Statement

Both AgentStudio and eInsta independently implement connector logic, schema introspection, auth handling, and data pipeline execution. The patterns are nearly identical but duplicated, with each adding connectors in isolation. The result:

- Adding a new connector (e.g. Kafka) requires touching 4+ files in 2 repos
- Auth patterns differ subtly between eInsta backend and AgentStudio backend
- eInsta's PySpark pipeline engine has no connector abstraction — it only reads/writes local files
- AgentStudio's 26-connector registry is a flat dict with procedural dispatch — hard to extend without modifying core files
- Neither system has a stable programmatic API surface (SDK) that third-party tools could depend on

**Goal:** Extract and generalise these patterns into a single open-source **SangamMW** middleware that:
1. Provides a unified `Connector` abstraction covering all 26+ data sources
2. Ships a pluggable pipeline engine (PySpark for large-scale, pandas for small-scale)
3. Exposes a REST + (optionally) gRPC API so any tool (AgentStudio, eInsta, or external) can consume it
4. Is designed for open-source contribution from day one

## 4. Module Breakdown

### 4.1 `sangam_mw.connectors` — Connector Plugin System

Every connector is a Python class implementing `BaseConnector`:

```python
class BaseConnector(ABC):
    connector_id: str               # "postgres", "mongodb", etc.
    family: ConnectorFamily         # sql | nosql | rest | storage | graph | cache | analytics | saas
    kind: ConnectorKind             # sql | mongo | rest | s3 | etc.

    @abstractmethod
    def connect(self, config: ConnectorConfig) -> ConnectionHandle: ...

    @abstractmethod
    def test(self, config: ConnectorConfig) -> TestResult: ...

    @abstractmethod
    def introspect_objects(self, handle: ConnectionHandle, schema: str | None) -> list[ObjectInfo]: ...

    @abstractmethod
    def introspect_columns(self, handle: ConnectionHandle, obj: str, schema: str | None) -> list[ColumnInfo]: ...

    @abstractmethod
    def sample(self, handle: ConnectionHandle, obj: str, limit: int) -> list[dict]: ...
```

**Subclasses (one per family):**
- `SqlConnector` — base for all 9 SQL dialects; parameterised via `SqlDialectSpec` (driver, port, JDBC URL fn)
- `MongoConnector`
- `RestConnector` — auth types resolved via `AuthProvider`
- `FileStorageConnector` — base for S3, GDrive, AzureBlob, OneDrive, SharePoint, FTP/SFTP
- `GraphConnector` — base for Neo4j
- `CacheConnector` — base for Redis
- `AnalyticsConnector` — base for BigQuery, Snowflake, Databricks
- `SaasConnector` — base for Jira, GitHub, HubSpot, Slack

**Registry:**
```python
CONNECTOR_REGISTRY: dict[str, type[BaseConnector]] = {}

def register_connector(cls: type[BaseConnector]):
    CONNECTOR_REGISTRY[cls.connector_id] = cls

def get_connector(connector_id: str) -> BaseConnector:
    cls = CONNECTOR_REGISTRY[connector_id]
    return cls()
```

This is a class-based registry (improvement over AgentStudio's flat dict). External packages can call `register_connector()` to add connectors without forking.

### 4.2 `sangam_mw.auth` — Auth Framework

```python
class AuthProvider(ABC):
    auth_type: AuthType

    @abstractmethod
    def apply(self, request: PreparedRequest, config: AuthConfig) -> PreparedRequest: ...

    @abstractmethod
    def refresh_if_needed(self, config: AuthConfig) -> AuthConfig: ...
```

Implementations: `BearerAuth`, `BasicAuth`, `ApiKeyHeaderAuth`, `ApiKeyQueryAuth`, `CustomHeadersAuth`, `OAuth2ClientCredentials`, `SalesforceJwtBearer`, `ServiceAccountAuth`, `AwsSignatureAuth`, `RsaKeyAuth`

Token refresh is handled transparently — OAuth2 and Salesforce tokens are cached with their expiry; `refresh_if_needed()` is called before every request.

---

### 4.3 `sangam_mw.connections` — Connection Lifecycle

```python
class ConnectionManager:
    def get_or_create(self, config: ConnectorConfig, ttl_seconds: int = 180) -> ConnectionHandle: ...
    def release(self, handle: ConnectionHandle): ...
    def health_check(self, handle: ConnectionHandle) -> bool: ...
    def close_all(): ...
```

- Pool keyed by `fingerprint(config)` (SHA-256 of non-secret fields + encrypted secret hash)
- Configurable TTL (default 180s, matching AgentStudio's pool)
- Health check on borrow (re-connect on stale)
- Thread-safe via `asyncio.Lock` per handle

### 4.4 `sangam_mw.pipeline` — Pipeline Engine

**DAG model:**
```python
class PipelineNode:
    node_id: str
    node_type: NodeType             # source | sink | transform
    subtype: str                    # "csv_source", "filter", "join", etc.
    config: dict                    # node-specific options
    connector_ref: str | None       # connector_id if this node uses a connector

class Pipeline:
    nodes: dict[str, PipelineNode]
    edges: list[tuple[str, str]]    # (source_node_id, target_node_id)
```

**Engine interface:**
```python
class PipelineEngine(ABC):
    @abstractmethod
    def validate(self, pipeline: Pipeline) -> ValidationResult: ...

    @abstractmethod
    def preview(self, pipeline: Pipeline, limit: int = 100) -> dict[str, list[dict]]: ...

    @abstractmethod
    def run(self, pipeline: Pipeline, output_config: OutputConfig) -> RunResult: ...
```

**Implementations:**
- `SparkEngine` — wraps eInsta's subprocess-isolated Spark runner; uses PySpark 3.5; appropriate for >1M rows
- `PandasEngine` — pure pandas, in-process, appropriate for <1M rows; no Spark required
- `EngineRouter` — selects engine based on estimated row count and availability

**New vs. eInsta:** The pipeline engine in v0.1 is connector-aware — a `SourceNode` can reference a `connector_id` to pull data directly from a database/API instead of only local files.

### 4.5 `sangam_mw.api` — REST API Surface

Endpoints:

```
POST   /connectors/{id}/test          Test a connection config
POST   /connectors/{id}/objects       List tables/collections/resources
POST   /connectors/{id}/columns       List columns for an object
POST   /connectors/{id}/sample        Sample rows from an object

POST   /connections                   Store encrypted connection (named)
GET    /connections                   List stored connections
DELETE /connections/{conn_id}         Remove a connection

POST   /pipelines/validate            Validate DAG structure
POST   /pipelines/preview             Execute and return preview rows
POST   /pipelines/run                 Execute and write outputs

GET    /health                        Health check
GET    /connectors                    List registered connectors + metadata
```

Auth for the API itself: JWT (same pattern as AgentStudio) with optional API-key mode for machine-to-machine.

---

### 4.6 `sangam_mw.sdk` — Python SDK (Client Library)

Thin wrapper so tools like AgentStudio/eInsta don't HTTP-call themselves:

```python
from sangam_mw import SangamMW

mw = SangamMW(base_url="http://localhost:8080", api_key="...")

# Test a connector
result = mw.connectors.postgres.test(host="...", port=5432, ...)

# Run a pipeline
result = mw.pipelines.run(pipeline_dict)
```

## 7. Key Design Principles

1. **Class-based plugins over flat dicts** — Enables inheritance, type safety, and third-party registration without forking.
2. **Subprocess isolation for Spark** — Keeps FastAPI process clean; same pattern as eInsta, proven in production.
3. **Fernet encryption for secrets at rest** — Consistent with both AgentStudio and eInsta Agent Studio backends.
4. **Single registry, dual consumption** — Same connector objects serve both the REST API and the Python SDK. No duplication.
5. **Engine-agnostic pipeline model** — `Pipeline` DAG is the source of truth; engine choice is a runtime decision.
6. **Open-source from day one** — Apache 2.0 license, public GitHub, semver, `CONTRIBUTING.md` before first release.

## 8. What This Replaces / Relates To

| Current code | Replaced by |
|---|---|
| `AgentStudio/backend/connector_registry.py` (flat dict) | `sangam_mw.connectors.registry` (class registry) |
| `AgentStudio/backend/database/introspect.py` (3300-line procedural) | Per-connector `introspect_*` methods |
| `eInsta/backend/execution/pipeline_runner.py` | `SparkEngine` + `PandasEngine` |
| `eInsta/backend/execution/graph.py` (topo sort) | `sangam_mw.pipeline.graph` (ported, slightly generalised) |
| `AgentStudio/backend/connections_store.py` | `sangam_mw.connections.store` |
| `AgentStudio/backend/auth.py` (REST connector auth) | `sangam_mw.auth.providers` |

AgentStudio becomes a **client** of SangamMW — its introspect routes proxy to the middleware, and its connector registry becomes a thin mapping from MW connector IDs to frontend UI metadata.

eInsta becomes a **client** of SangamMW — its pipeline runner delegates to `SparkEngine`/`PandasEngine`, and its DB connectors delegate to the MW connector layer.

## 9. Open Questions (link to debate)

See [`OPEN_QUESTIONS.md`](OPEN_QUESTIONS.md) for all unresolved design decisions that should be debated before locking v0.2.

**Top 5 questions to resolve first:**
1. Should this be a **library** (import directly) or a **service** (call over HTTP)?
2. Is **PySpark a hard dependency** or optional/pluggable?
3. **Naming**: "SangamMW"? "sangam-middleware"? Something more domain-neutral?
4. Should v1 include the **Pipeline Engine**, or ship connectors-only first?
5. **Connection pooling strategy**: TTL-based (current) vs. min/max pool size (production standard)?
